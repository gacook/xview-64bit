# XView 3.2 — 64-bit Linux Porting Notes

This document describes every change made to adapt XView 3.2 (`xview-3.2p1.4-25.16`) to
64-bit Linux (AMD64/x86_64).  It is intended for maintainers who need to understand *why*
a change was made before touching it, and as a guide for porting to additional platforms.

---

## 1. Architecture declaration (`config/host.def`)

```c
#undef i386Architecture
#define AMD64Architecture
#define DefaultCDebugFlags -O0
```

The XView Imake configuration tree inherits from X11R6 templates that key many decisions
(ABI flags, library suffix, 64-bit data model) on the architecture symbol.  Without
`AMD64Architecture` the build defaults to 32-bit i386 assumptions.

---

## 2. Disabling `_FORTIFY_SOURCE` and stack protection (`Build-LinuxXView.bash.amd64`)

```bash
EXTRA_DEFINES = ... -U_FORTIFY_SOURCE -D_FORTIFY_SOURCE=0
CFLAGS       += -fno-stack-protector ...
```

Modern glibc enables `_FORTIFY_SOURCE=2` by default in any build that passes `-O1` or
higher.  At that level, `__builtin___memcpy_chk` and friends check the destination buffer
size against the copy size at compile-time and runtime.

XView allocates fixed-size internal window-object buffers sized for the original SunOS
ABI.  On 64-bit Linux the same structs are larger (pointers doubled, alignment padding
added), so glibc's checker rejects copies into them as overflows — even though the actual
memory layout is correct and the code has worked safely for 30+ years.

`-U_FORTIFY_SOURCE -D_FORTIFY_SOURCE=0` forces the level back to 0 (unchecked wrappers).
`-fno-stack-protector` suppresses stack canaries for the same class of legacy buffer
patterns.

**Do not remove these flags** without first auditing every XView internal buffer against
the 64-bit struct sizes.

---

## 3. File-descriptor iteration fix (`lib/libxview/notify/ndis_d_pri.c`)

**Function:** `ndis_send_ascending_fd()` (line 111)

### Root cause

The original loop iterated over the bytes of an `fd_set` bitmask by shifting a sentinel
value through an `unsigned long`:

```c
unsigned long byte;
for (byte = 0xff; byte != 0L; byte <<= NBBY)
    if (bits_ptr->fds_bits[i] & byte) { ... }
```

On 32-bit Linux `unsigned long` is 4 bytes = 32 bits = 4 iterations (one per byte of the
32-bit `__fd_mask`).  On 64-bit Linux `unsigned long` is 8 bytes, so `byte <<= 8` takes
8 iterations before all bits fall off — but `fds_bits[i]` is only 8 bytes wide too, so
this is consistent.  **The real problem** is that the termination test `byte != 0L` was
reached only when all bits had shifted out, which on 64-bit happened after exactly 8
shifts, but the address arithmetic `fd = byteNum * NBBY + i * NFDBITS` computed byte
addresses beyond the allocated `fd_set` when `i` was at its maximum value and `byteNum`
exceeded what the current mask element could represent.  The result was a memory read past
the end of the `fd_set`, corrupting the stack and producing a core dump on systems
configured for more than 1024 file descriptors.

### Fix

```c
uint32_t byte;                          /* fixed 32-bit sentinel */
int mask_bytes = sizeof(__fd_mask);     /* 4 on 32-bit, 8 on 64-bit */

for (byte = 0xff, byteNum = 0; byteNum < mask_bytes;
     byte <<= NBBY, byteNum++)
    if (bits_ptr->fds_bits[i] & byte) { ... }
```

Two independent corrections:

* `uint32_t` instead of `unsigned long` ensures the sentinel is always 32 bits and shifts
  within a well-defined range regardless of architecture word size.
* Replacing the sentinel-exhaustion test `byte != 0L` with the explicit count
  `byteNum < mask_bytes` ties iteration count directly to the actual byte width of
  `__fd_mask`, making the loop correct on both 32-bit and 64-bit systems.

## 4. `libtirpc` linker ordering (`config/XView.tmpl`, `Build-LinuxXView.bash.amd64`)

Modern Linux no longer ships Sun RPC in glibc (removed in glibc 2.32); it lives in
`libtirpc`.  Several XView clients include `<rpc/*.h>` and call RPC functions.

### Why position matters

GNU `ld` (and gold/lld in default mode) uses a single-pass left-to-right symbol
resolution strategy.  A library placed *before* the object files that reference it is
scanned before those undefined symbols exist, so the linker marks the library as
"not needed" and drops it.  The symbols are never resolved, and the link fails with
`undefined reference to ...`.

### Solution

`-ltirpc` is placed in `XVCLIENTMISCLIB` in `config/XView.tmpl` (line 379/383):

```
XVCLIENTMISCLIB = -ltirpc -lncurses          # non-i18n build
XVCLIENTMISCLIB = -lw -ltirpc -lncurses      # i18n level 4 build
```

This macro expands *after* the client object files in the final link command generated by
Imake's `XViewClientLibs` expansion, so the linker encounters `-ltirpc` only after all
undefined RPC symbols have been recorded.

`-ltirpc` must **not** appear in `LOCAL_LDFLAGS` (which the build script prepends before
object files).

---

## 5. `libncurses` addition (`config/XView.tmpl`)

Some `contrib/examples/` clients use terminal-manipulation functions (`initscr`, `endwin`,
etc.) from ncurses.  These were historically provided by the system `libc` on SunOS but
are a separate library on Linux.  `-lncurses` is appended to `XVCLIENTMISCLIB` alongside
`-ltirpc` (see section 4).

---

## 6. `OPENWINHOME` default

Set to `/usr/openwin` in `Build-LinuxXView.bash.amd64` and propagated via
`-DOPENWINHOME_DEFAULT=\"/usr/openwin\"` in `EXTRA_DEFINES`.  This gives XView its own
installation prefix separate from `/usr`, avoiding file conflicts with X11 packages and
matching the path hard-coded in many XView resource files and apps.

---

## 7. Deprecated BSD signal API in `clients/olvwm-4.1/olwm.c`

`sigblock()`, `sigsetmask()`, and `sigmask()` are BSD 4.2 functions that glibc marks
`__deprecated__`.  They still work (thin wrappers around `sigprocmask`), but will
produce `-Wdeprecated-declarations` warnings.

The code reaches these functions because the original guards only tested `#ifdef SYSV`
(which is not defined on Linux), so Linux falls into the BSD `#else` branches.  The
`__linux__`-specific additions added later for `waitpid` (line 728) were never extended
to the signal-masking code.

These functions are **not yet broken** on current glibc, but the correct fix is to extend
the SYSV guards:

```c
/* Replace: */
#if defined(SYSV)
    sighold(SIGCHLD);
#else
    oldmask = sigblock(sigmask(SIGCHLD));     /* BSD / deprecated */
#endif

/* With: */
#if defined(SYSV) || defined(__linux__)
    sighold(SIGCHLD);
#else
    oldmask = sigblock(sigmask(SIGCHLD));
#endif
```

Or replace the BSD calls with POSIX `sigprocmask()` directly.
